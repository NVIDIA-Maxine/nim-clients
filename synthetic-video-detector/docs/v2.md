
# NVIDIA Synthetic Video Detector NIM Client

This package provides a sample client that demonstrates interaction with the NVIDIA Synthetic Video Detector NIM. The client allows you to analyze video files to detect whether they are synthetic/fake or real.

> **Client version:** This is the **v2** client for a self-hosted Synthetic Video Detector NIM (self-hosted gRPC plus pre-signed S3 URL ingest). It targets the `nvidia.ai4m.syntheticvideodetector.v1` gRPC API and does not support the NVCF-hosted Try API. Use the [v1 client](v1.md) for an NVCF / Try API server. The v1 and v2 APIs are not cross-compatible; pointing this client at a v1 server fails with an `UNIMPLEMENTED` error and a message telling you to switch clients.

The detector is designed to **identify synthetic (AI-generated) videos**. The default classification threshold is set conservatively to minimize the chance of missing any synthetic video. You can adjust the classification threshold to suit your use case (see [Threshold and use cases](#threshold-and-use-cases)).

## Getting Started

NVIDIA AI4M NIM Client packages use gRPC APIs. The following instructions demonstrate the Synthetic Video Detector NIM by using a Python client. This client connects to a self-hosted Synthetic Video Detector NIM server.

## Prerequisites

- Access to NVIDIA Synthetic Video Detector NIM container and service.
- The NIM accepts MP4/QuickTime, Matroska, and WebM input with H.264/AVC, H.265/HEVC, AV1, VP8, or VP9 video (audio optional). See [Supported Formats](#supported-formats) for the full matrix and known limitations.
- Variable Frame Rate (VFR) input is supported; per-frame presentation timestamps drive the emitted results.
- Ensure that you have Python 3.10 or later installed on your system. For download and installation instructions, see [Download Python](https://www.python.org/downloads/).
- A GPU whose NVDEC hardware decoder supports your input. AV1 decoding requires an Ampere or newer GPU. For per-GPU capabilities and driver/CUDA requirements, see the [Synthetic Video Detector Support Matrix](https://docs.nvidia.com/nim/maxine/synthetic-video-detector/latest/support-matrix.html) and the [NVIDIA Video Encode and Decode GPU Support Matrix](https://developer.nvidia.com/video-encode-and-decode-gpu-support-matrix-new).

## Usage Guide

### 1. Clone the Repository

```bash
git clone https://github.com/NVIDIA-Maxine/nim-clients.git

# Go to the 'synthetic-video-detector' folder
cd nim-clients/synthetic-video-detector/
```

### 2. Install Dependencies

```bash
# Install all the required packages using requirements.txt file
pip install -r requirements.txt
```

### 3. Compile the Protos (optional)

If you want to use the client code provided in the GitHub client repository, you can skip this step.

The proto files are available in the `synthetic-video-detector/protos` folder. The v2 API lives in `protos/proto/nvidia/ai4m/` (the `syntheticvideodetector` service plus the shared, media-agnostic `ingest` proto it imports); the v1 API lives alongside it in `protos/proto/nvidia/maxine/`. You can compile them to generate client interfaces in your preferred programming language. For more details, refer to [Supported languages](https://grpc.io/docs/languages/) in the gRPC documentation.

The following example shows how to compile the protos for Python on Linux and Windows. The compile script builds both API generations in one pass.

#### Python

The `grpcio` version needed for compilation can be referred at `requirements.txt`

**To compile protos on Linux:**
```bash
# Go to synthetic-video-detector/protos/linux/ folder
cd synthetic-video-detector/protos/linux/

chmod +x compile_protos.sh
./compile_protos.sh
```

**To compile protos on Windows:**
```bash
# Go to synthetic-video-detector/protos/windows/ folder
cd synthetic-video-detector/protos/windows/

./compile_protos.bat
```

The compiled proto files appear in the `nim-clients/synthetic-video-detector/interfaces` directory, mirroring the proto packages. The v2 stubs land in `interfaces/nvidia/ai4m/` and are imported as:

```python
from nvidia.ai4m.syntheticvideodetector.v1 import syntheticvideodetector_pb2
from nvidia.ai4m.ingest.v1 import presigned_url_pb2
```

### 4. Host the NIM Server

Before running the client part of Synthetic Video Detector, set up a server. 
The simplest way to do that is to follow the [quick start guide](https://docs.nvidia.com/nim/maxine/synthetic-video-detector/latest/index.html) in the documentation for setting up the Synthetic Video Detector NIM.

### 5. Run the Python Client

Go to the v2 `scripts` directory (from the `synthetic-video-detector` folder):

```bash
cd scripts/v2
```

#### Basic Usage

```bash
python3 synthetic-video-detector.py \
  --target <server_ip:port> \
  --video-input <input_video_file_path> \
  --save-csv [filename]
```

Running the Python client script with no arguments uses the default arguments. All arguments are listed in the [Command-Line Arguments](#command-line-arguments) table below.

#### Pre-signed URL (S3 Ingest) Usage

Instead of streaming a local file, the client can send a single pre-signed HTTPS URL and let the NIM download and analyze the object. Use `--presigned-url` in place of `--video-input` (the two are mutually exclusive). The client is a thin pass-through: the NIM performs all URL validation (HTTPS, host allowlist, expiry, SSRF, checksum, size, content-type).

```bash
python3 synthetic-video-detector.py \
  --target <server_ip:port> \
  --presigned-url "<https-presigned-url>" \
  --presigned-url-provider s3 \
  --save-csv [filename]
```

### 6. Understanding the Results

The Synthetic Video Detector analyzes videos by processing them per frame and provides the following output:

#### Console Output

The client displays:
- **Final statistics**:
  - Total frames processed
  - Final probability (0.0 to 1.0, where >0.44 indicates synthetic/fake at the default threshold)
- **Verdict**: SYNTHETIC/FAKE or REAL with confidence percentage

#### CSV Output

When requested with `--save-csv`, a CSV is generated containing:
- **index**: Frame index
- **probability**: Per-frame probability computed from the model logit using a sigmoid transform

The CSV format allows for detailed analysis of detection results across the entire video.

#### Threshold and use cases

The service returns a calibrated synthetic probability and applies no threshold itself; the client decides. The default classification threshold is **0.44** (the balanced V2 operating point), which gives equal weight to correctly identifying synthetic and authentic content. Lower it to **0.26** (the conservative operating point) to catch more synthetic content, at the cost of more false positives on authentic videos.

| Threshold | Behavior | Recommended Use Case |
|-----------|----------|----------------------|
| **0.44** (default, balanced) | Balanced -- provides equal weight to correctly identifying both synthetic and authentic content. | General-purpose classification where both false positives and false negatives should be minimized. |
| **0.26** (conservative) | Conservative -- prioritizes catching all synthetic content. May produce more false positives on authentic videos. | High-stakes screening where missing a synthetic video is unacceptable. |

Adjust the threshold according to your use case. You can modify the `CLASSIFICATION_THRESHOLD` value in `scripts/v2/constants.py` based on your requirements.

### 9. Important Usage Notes

#### Supported Formats

All decoding is performed on the GPU using NVDEC.

| Container | File extensions | Video codecs |
|-----------|-----------------|--------------|
| MP4 / QuickTime | `.mp4`, `.mov`, `.m4v` | H.264/AVC, H.265/HEVC, AV1 |
| Matroska | `.mkv` | H.264/AVC, H.265/HEVC, AV1, VP8, VP9 |
| WebM | `.webm` | VP8, VP9 |

Because decoding runs entirely on NVDEC, the decodable set of codecs, pixel formats, chroma subsampling, and bit depths is whatever the target GPU's NVDEC hardware decoder supports. AV1 requires an Ampere or newer GPU. For authoritative per-GPU capabilities, see the [NVIDIA Video Encode and Decode GPU Support Matrix](https://developer.nvidia.com/video-encode-and-decode-gpu-support-matrix-new).

The maximum input resolution is also bounded by NVDEC and varies by codec and GPU architecture: H.264/AVC decodes up to 4096x4096, while H.265/HEVC, VP9, and AV1 decode up to 8192x8192 on Ampere, Ada Lovelace, and Hopper GPUs (Blackwell decodes up to 8192x8192 for all supported codecs). See the [NVDEC Video Decoder API Programming Guide](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/nvdec-video-decoder-api-prog-guide/index.html) for the authoritative per-architecture limits.

Audio is ignored; any audio codec in a supported container is fine.

**Known limitations** (observed on a 216-file format sweep):

| Limitation | Detail |
|------------|--------|
| Chroma subsampling | **4:2:2 is not supported** (`yuv422p`, `yuv422p10le`). 4:2:0 decodes across all supported codecs. **4:4:4 is codec-dependent**: H.265/HEVC 4:4:4 (`yuv444p10le`, `yuv444p12le`) decodes, but **H.264 4:4:4 (8-bit, High 4:4:4 Predictive) is rejected** by NVDEC. AV1 4:4:4 was not evaluated. |
| 10-bit H.264 | **H.264 High 10 fails to decode.** 10-bit H.265 (Main 10) and 10-bit AV1 work. |
| Unsupported codecs | MPEG-4 Part 2, MPEG-2, ProRes, MJPEG, WMV, Theora, DV, and raw video are rejected with a clear `INVALID_ARGUMENT` error. |
| Unsupported containers | Raw/other containers such as `.yuv`, `.y4m`, `.ts`, `.m2ts`, `.avi`, `.flv`, `.mpg`, `.vob`, `.asf`, `.ogv`, `.mxf`, `.3gp` are rejected. |
| Very long inputs | Multi-hour inputs may exceed the request deadline. Segment long videos before submitting. |

> **Note:** `.mov` files carrying ProRes are rejected — the container is supported, the codec is not.

#### Input Modes

The client supports two mutually exclusive input modes:

- **Byte streaming** (`--video-input`): the local video file is uploaded to the NIM in chunks.
- **Pre-signed URL / S3 ingest** (`--presigned-url`): the client sends a single pre-signed HTTPS URL and the NIM downloads, integrity-checks, and analyzes the object. Use `--presigned-url-provider s3` for AWS S3 pre-signed URLs. Optionally provide `--presigned-checksum`/`--presigned-checksum-type`, `--presigned-expected-size`, and `--presigned-content-type` so the server can verify the download. All validation is performed server-side by the NIM.

#### Processing Modes: Streaming vs Transactional

For the byte-streaming path, the NIM processes the upload in one of two modes, chosen automatically from the input layout:

- **Streaming mode (recommended)**: Used only for *streamable* (faststart) **H.264 MP4** input, where the `moov` metadata atom sits at the front of the file. The NIM begins decoding and running inference as soon as the first frames arrive, overlapping upload and inference. This delivers the lowest latency and disk I/O and scales best to large files.
- **Transactional mode**: Used for **all other input**, including non-faststart MP4, H.265/AV1/VP8/VP9 streams, Matroska/WebM containers, and pre-signed URL ingest. The input is received in full before decoding begins.

The NIM auto-detects streamable input and enables streaming mode; no client flag is required. The client prints which mode will be used based on your input file.

| Aspect | Streaming Mode | Transactional Mode |
|--------|----------------|--------------------|
| Applies to | Streamable (faststart) H.264 MP4 | All other input: non-faststart MP4; H.265, AV1, VP8, VP9; MKV/WebM; pre-signed URL ingest |
| Upload/inference overlap | Yes | No (full receive first) |
| Latency | Lowest | Higher |
| Best for | Large files, low-latency use | Everything else |

To convert a non-streamable video into a streamable one, see [Convert a Video to Streamable Video with FFmpeg](#10-convert-a-video-to-streamable-video-with-ffmpeg).

#### How It Works

1. **Input**: The client either uploads the video file to the NIM service in chunks (default 1MB per chunk) or sends a single pre-signed URL for the NIM to download.
2. **Processing**: The service analyzes the video by:
   - Automatically selecting streaming or transactional mode (streaming only for faststart H.264 MP4)
   - Extracting and processing video frames
   - Running the DINO-based deep learning model on each frame
   - Computing per-frame detection scores (logits)
3. **Response**: The service streams back:
   - A one-shot service info banner (NIM version, model version, request ID)
   - Per-frame results as they are processed
   - Keep-alive messages during processing
   - Final aggregated result (mean logit, synthetic probability, total frames)
4. **Output**: The client displays:
   - Final verdict (SYNTHETIC/FAKE or REAL)
   - Optional detailed CSV results

### 10. Convert a Video to Streamable Video with FFmpeg

Streaming mode requires a *streamable* (faststart) **H.264** MP4, where the `moov` metadata atom is at the start of the file. To convert a regular MP4 into a streamable one:

```bash
ffmpeg -i input.mp4 -c copy -movflags +faststart output_streamable.mp4
```

Other inputs (H.265, AV1, VP8/VP9, MKV/WebM) are always processed transactionally, so converting them to faststart has no effect.

The `-movflags +faststart` flag moves the metadata to the beginning of the file so the NIM can begin processing before the whole file is uploaded. A helper script is also provided:

```bash
../../../tools/convert_media_to_streamable.sh input.mp4 output_streamable.mp4
```

Then pass the streamable file with `--video-input`:

```bash
python3 synthetic-video-detector.py --target 127.0.0.1:8001 --video-input output_streamable.mp4
```
